# Backend игрового сервера

## Выбор БД и данные

Используется **PostgreSQL**: транзакции, внешние ключи и конкурентные обновления
подходят для многопользовательского сервера и позволяют сохранять статистику без
потери при одновременных запросах. Асинхронный драйвер — `asyncpg`, работа с данными
— SQLAlchemy 2.0. Alembic управляет схемой; приложение не создаёт таблицы при запуске.

Таблицы:

| Таблица | Содержимое |
| --- | --- |
| `users` | UUID гостя, отображаемое имя, время создания UTC |
| `player_stats` | Число подключений, успешных запросов к Qwen и успешных распознаваний Whisper; одна запись на гостя |
| `scenarios` | Идентификатор, название, описание и системная инструкция NPC |

Первая миграция создаёт таблицы и сценарий `interview`. Счётчики увеличиваются
атомарными SQL-обновлениями. Ошибки ИИ не увеличивают статистику.
Счётчик распознаваний учитывает успешный ответ сервиса, включая пустой текст при тишине.
Координаты находятся в памяти: после перезапуска или переподключения позиция равна нулю.
Аудио не сохраняется в постоянное хранилище. Временный буфер загрузки управляется FastAPI.

## Подготовка и запуск вручную

Ниже команды для самостоятельного выполнения из корня репозитория в PowerShell.
Во время разработки backend установка, миграции, запуск и тесты не выполнялись.
Контейнеры Qwen и Whisper уже работают; скачивать их образы или веса повторно не нужно.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` задайте параметры PostgreSQL и `DATABASE_URL` в формате
`postgresql+asyncpg://USER:PASSWORD@HOST:PORT/DATABASE`. Для пароля со специальными
символами используйте URL-кодирование в строке подключения. Значения `game` в примере
предназначены для локальной разработки. База должна существовать до применения миграций.

Если PostgreSQL ещё не подготовлен, в `docker-compose.yaml` добавлен сервис `db` с
постоянным томом `postgres_data`. Запуск только БД, не затрагивающий ИИ-сервисы:

```powershell
docker compose up -d db
```

Эта команда при отсутствии образа PostgreSQL скачает его; уже работающие ИИ-модели
не скачиваются. Можно вместо Docker использовать существующий сервер PostgreSQL,
указав его адрес в `.env`. Переменные `POSTGRES_*` применяются контейнером только
при первой инициализации пустого тома. После готовности БД:

```powershell
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 0.0.0.0 --port 8000 --workers 1 --ws-max-size 4096
```

Запускайте **один процесс**: игровой мир и список WebSocket-подключений находятся
в его памяти. Несколько процессов потребуют общего слоя обмена состоянием, которого
в текущем ТЗ нет. PostgreSQL хранит данные независимо от перезапусков backend.

После запуска описание HTTP API доступно по адресу `http://localhost:8000/docs`.
`CORS_ORIGINS` — JSON-массив адресов фронтенда с протоколом и портом без завершающего `/`.
Он используется также для проверки заголовка `Origin` WebSocket. Клиенты без `Origin`
могут подключаться. Backend работает на хосте, поэтому ИИ-сервисы доступны через localhost.

## HTTP API

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/players` | Создать гостя и нулевую статистику |
| `GET /api/players/{player_id}/stats` | Получить статистику гостя |
| `GET /api/scenarios` | Получить сценарии без внутренних инструкций NPC |
| `POST /api/ai/chat` | Получить текстовый ответ NPC |
| `POST /api/ai/transcribe` | Получить текст из аудиозаписи |

Создание гостя: JSON `{"display_name":"Игрок"}`. Имя — 1–40 символов после удаления
пробелов по краям. Возвращается HTTP 201 и объект с `id`, `display_name`, `created_at`.
Без имени используется `Гость`. Фронтенд сохраняет `id` и использует его для WebSocket
и запросов к ИИ; повторное создание гостя не требуется при каждом переподключении.

Запрос Qwen:

```json
{
  "player_id": "UUID из ответа создания гостя",
  "scenario_id": "interview",
  "message": "Я занимался разработкой командного проекта."
}
```

Ответ: `{"reply":"Текст NPC"}`. Сообщение — 1–1000 символов. Сервер передаёт
системную инструкцию сценария и текущую реплику в
`http://localhost:8081/v1/chat/completions`, без потоковой выдачи, с ограничением
ответа в 256 токенов. История диалога на этом этапе не сохраняется и не пересылается.
Модель задаётся переменной `QWEN_MODEL`.

Распознавание: `multipart/form-data`, поля `player_id` и `file` (аудиозапись).
Лимит аудиофайла по умолчанию 10 МиБ (`MAX_AUDIO_BYTES`). Принимаются MIME-типы
`audio/wav`, `audio/x-wav`, `audio/wave`, `audio/webm`, `video/webm`, `audio/ogg`,
`audio/mpeg`, `audio/mp4`, `audio/flac`, включая параметры кодека после `;`.
Например, запись MediaRecorder можно передать как `audio/webm;codecs=opus`.
WAV дополнительно проверяется по заголовку RIFF/WAVE; декодирование и проверку
остальных форматов выполняет Whisper. Конвертация браузерных форматов использует
уже указанный в Docker-конфигурации Whisper флаг `--convert` и требует поддержки
конвертации внутри его образа; WAV можно передавать напрямую.
Backend передаёт файл в `http://localhost:8082/inference`, с `response_format=json`
и автоматическим выбором языка. Возвращается `{"text":"Распознанный текст"}`.
Затем фронтенд может отправить этот текст в `/api/ai/chat`, чтобы получить ответ NPC.
Пустой текст означает, что речь не распознана; отправлять его в чат не нужно.

Ошибки: 404 — неизвестный игрок или сценарий; 413 — слишком большой аудиофайл;
415 — неподдерживаемый формат или неверный заголовок WAV; 422 — неверные поля запроса
или пустой файл; 502 — ИИ недоступен или вернул
неверный ответ; 504 — превышен таймаут ИИ (`AI_TIMEOUT_SECONDS`, по умолчанию 120 секунд
для сетевых операций). На каждый ИИ-сервис допускается до двух одновременных запросов;
остальные ожидают свободного места. Ожидание места не входит в сетевой таймаут.

## WebSocket и Three.js

После создания гостя открыть `ws://localhost:8000/ws/{player_id}`. Для HTTPS использовать
`wss://`. Одновременно допускается одно соединение на гостя; повторное соединение
отклоняется, не отключая первое. Несуществующие гости также отклоняются.

После входа, принятого движения или выхода любого игрока сервер рассылает всем
полный снимок общего мира:

```json
{
  "type": "state",
  "revision": 1,
  "players": [
    {
      "id": "UUID игрока",
      "display_name": "Игрок",
      "position": {"x": 0.0, "y": 0.0, "z": 0.0},
      "rotation_y": 0.0
    }
  ]
}
```

Фронтенд заменяет локальный список игроков содержимым `players`; отсутствующие в снимке
игроки вышли. Собственного игрока определяет по UUID. `revision` возрастает в пределах
работы процесса. Для медленных клиентов ожидающий снимок заменяется свежим, поэтому
пропуски номеров нормальны. Отправка имеет таймаут 5 секунд и не блокирует других игроков.

Клиент передаёт только собственные координаты и поворот, без идентификатора игрока:

```json
{
  "type": "move",
  "position": {"x": 1.5, "y": 0.0, "z": -2.0},
  "rotation_y": 1.57
}
```

Координаты соответствуют осям Three.js, поворот вокруг Y — в радианах.
Координаты ограничены диапазоном ±10000, поворот — приблизительно ±2π;
NaN и бесконечности запрещены. Сервер принимает движения не чаще 20 раз в секунду
от одного игрока, более частые сообщения игнорируются. Фронтенду следует отправлять
движения с интервалом не менее 50 мс, включая финальную позицию после остановки.
Физика, коллизии и проверка скорости в текущий backend не входят.

Некорректное сообщение или бинарный кадр закрывают соединение с кодом 1008;
слишком длинное сообщение — 1009. При разрыве соединения игрок удаляется из мира,
остальные получают новый снимок. Профиль и статистика остаются в PostgreSQL.

## Границы реализации

Авторизации нет: UUID идентифицирует гостя, но не подтверждает право доступа к нему.
TTS, собственные модели, фронтенд, оценивание ответов, боты и полный игровой цикл
не реализуются в рамках этого задания. Используются существующие Qwen и Whisper.
